# EvoCut：参考片复刻与成片质量经验

来源：Opus / GPT 视频对比项目的实际返工与审查；2026-10-07 用户明确要求将总结的28条经验记住并加入 EvoCut。以下是可复用的制作判断，不代表所有案例已完成、达到参考片水平，或经过受控模型评测。

## 何时读取

- **参考片复刻、对比优化、用户反馈“差很多 / 动态不足 / 字体不对”**：读执行流程、对应经验和审查记录要求。
- **新作或较大的视觉修改**：按实际问题读取字体构图（4–5）、动作与风格（6–18）、状态与内容（19–22）、交付审查（23–28）。不必把复刻流程套在无参考的新作上。
- **改一个字、调整单个参数、纯技术检查、只导出已有工程**：完成所请求的操作和受影响部分检查；不额外启动分镜访谈、全片重做或风格改造。
- **网页手机展示**：25的网页部分只在交付包含播放器/展示站时适用，不自动扩展成建站任务。

用户当前选择、项目规格和已生效的授权优先。沿用已确认的画幅、声音和品牌；查看当前项目配置，不将其他项目的画幅偏好自动套用。本文不新增审批节点、不授权花费或外部发布，也不要求再次询问已经授权的步骤。

## 执行流程

1. **建立参考依据**：读原 prompt、附件和实际参考视频；记录可访问范围、缺失素材、时长差异和已知后续修改。未看到的部分明确标记，不能凭缩略图声称看完整片。
2. **按语义拆镜头**：记下每段的主对象、必须发生的动作、字体/构图、镜头与材料变化、声音节拍、转场接点。时长不同的版本按“同一动作”对照，保留各自时间戳。
3. **定位最大差距**：说明具体时间段、可见问题、原因和拟改行为。先解决缺失动作、字体、对象连续性与镜头关系，再决定是否增加装饰。需要新机制时先验证代表性的关键动作片段。
4. **实施和复查**：使用所属工作流和 core/runtime 合同；复查新效果的副作用，如亮轨吞字、跳跃撞线、遮罩脱离。问题仍在就继续修正该段，不能用同类通用动效覆盖反馈。
5. **审最终文件**：结合实际播放、全线抽样、关键区间密采、原尺寸和目标手机尺寸；音频单独记录实际试听状态。技术、视觉、声音、参考差距分别给结论。
6. **交付与版本关联**：保存最终文件身份、所查范围、修复项和剩余差异。仅完成部分或尚未试听时按真实范围交付，不把“技术通过”写成“整体达到参考水平”。授权发布时核对页面使用的确为审过的文件。

没有必要为每次小修改新增一套文档。复刻或复杂返工把这些字段写进已有 design / notes / QA 记录即可；需要记录格式时使用文末字段。

## 28条经验

### 1. 原始 prompt 是动作与内容的验收依据

拆出主体、动作顺序、场景、风格、镜头、声音、时长和附件依赖。示波器案例要求扫描、余辉与相位合并，普通淡入缺少其核心过程。先核对必须发生的事情，再安排视觉表达；不以相同标题和配色代替相同内容。

### 2. 公开的一句话不代表完整输入条件

核查私有品牌资产、照片、代码库、附件及作者后续追问。缺失时按已有用户选择使用公开或独立素材并注明差异；没有这类授权且关键材料无法替代时，才提出必要问题。已有本地或公开素材走合适的采用/导入路径，供应商安装、登录和付费生成只在当前任务确实需要且有相应授权时处理。复刻示意、产品实录、离线演示和真实执行要明确区分；这些样本不支持通用的模型胜率或“一次生成”结论。

### 3. 对照连续动作和语义时刻

关键静帧用于分析字体与构图，连续播放用于判断速度、重心、停顿和镜头交接。对不同时长的版本，分别记录“脚触踏板”“答案变正确”等语义时刻，避免只比较相同秒数。静帧接近不证明动作接近。

### 4. 字体有角色，加载结果需要验证

分别选择主标题、强调、正文和数据字体，结合宽窄、字重、斜体、字面比例与品牌气质。实际加载字体后检查中英文字符和备用字体；字号、行距、字距、光学居中一起处理。某案例使用 Didot / Geist / Changa One 等是局部设计选择，不是通用品牌规定。

### 5. 排版包含阅读时间

为文字的进入、停留和退出留出阅读窗口。阵容名单按日期和层级分段；复杂步骤依次展开。不要通过缩小整张画面解决内容拥挤，先减少同屏竞争、分时呈现或调整断行；数字、单位和关键短语保持完整。

### 6. 动感有主次、速度变化和停顿

确定主动作、辅助反应与背景气氛，设计蓄势、加速、冲击、缓冲和落稳。避免所有元素同速摆动或无休止循环。阅读停顿和有意静止是有效设计；“动态不足”不等于每个元素每帧都要运动。

### 7. 手绘质感包含离散重绘的节奏

在适合的手绘片中使用确定性的线条重绘、局部偏移和线宽变化，保护阅读层与需要稳定的背景。案例14抽查片段约每3帧变化一次（30fps下约10次/秒），这是该片段的参考节奏，不能推广到所有手绘片。局部线条更新和全画面摄像机抖动分别处理。

### 8. 主体内部动作需要真正发生

拆出有意义的局部自由度：缝纫机的针、轮、脚踏与布料，飞机的飞行，人物的姿态。相互关联的部件协调运动；镜头位移不承担缺失的主体动作。也不要为本应静止的段落添加随机动作以满足帧差指标。

### 9. 沙画表现沉积、扫除和中间状态

用局部密度、稳定颗粒、逐步形成/擦除的轮廓表达材料。主体动作与扫沙过程可以分别控制，但应构成连续演变。棕色线稿叠噪点、只动纸纹或镜头，都不足以表现原片所需的沙画过程。

### 10. 油画、印刷等风格需要各自的材料规则

油画笔触参与形体与光照形成，保留连续解剖结构；案例35的12次/秒绘画更新来自其 prompt，不是全局帧率。印刷需要分色版、套色/错版与挖空；案例113曾因无差别叠色把黄星变脏黑。修材质时同时保护焦点和文字，不靠统一噪声替代所有风格。

### 11. 动作遵守连接、长度与接触约束

脚随脚踏、腿段长度保持、膝盖由约束求解；水流连接瓶口和变化中的液面，杯壁正确遮挡；机械碰撞几何与可见几何一致。优先验证连接点、支撑面和最大运动范围，避免各部件独立摆动造成滑动、穿透和瞬移。

### 12. 自然感依赖连续因果

风改变后速度逐渐响应；压力传播按距离产生延迟；烟花升空减速，碎片有阻力和重力；落水后物体遵守水面状态。需要时用速度积分、固定步长模拟或已计算姿态。艺术物理只按其验证范围描述，不宣称科学仿真或完全被动机械系统。

### 13. 角色表演包含意图和反应

根据叙事安排目光、预备动作、重心转移、落地缓冲与周围角色反应。木字母的犹豫到起跳、企鹅的注视到反馈形成表演段落。刀光由剑尖历史轨迹产生，落地特效由落地触发；通用呼吸或上下浮动不能承担这些表演。

### 14. 保留同一个对象的身份

让同一张图片、文件、表单或幻灯片走完输入—操作—结果的过程，必要时保留可识别编号。移动过程中控制副本可见性，落位后才显示完成。粒子变形也尽量保留可跟踪的映射，避免无关联粒子集突然切换。

### 15. 空间感由相对运动和遮挡建立

设计前后层次、视差、相机路径、掠过速度和遮挡关系。案例143的薄光线需增加亮核、不同尺度晕光与纵深轨迹；纸张各自弯曲、展开和聚拢。全画面平移或单层阴影不能补全所需空间关系。实现仍遵守所选 runtime 的 seek 合同。

### 16. 分辨形体问题和材质问题

轮廓接近却观感差时，检查粗糙度、反射、透明、边缘高光、阴影和光照层次，再决定是否加几何。木头、纸、塑料、金属、玻璃分别处理。程序模型、公开素材与高细节原资产的差距如实保留，不承诺无法验证的同等级真实感。

### 17. 特效增强后重新检查可读性

发光、颗粒和纹理变化可能吞没主体或字幕。案例143增强黄色光轨后，使用随字幕淡出的局部柔暗底与描边保护文字。检查亮度峰值和手机缩小后的对比；不要默认把全片压暗或用固定描边参数解决一切。

### 18. 检查运动包络和峰值

检查入场途中、跳跃最高点、放大峰值、旋转扫过范围和退出。案例144通过错开文档/说明时序、降低跳高解决相交。静止布局通过后，仍要查看动态极值，尤其字幕与角色、进度条等相邻元素。

### 19. 多处表现共用一份状态和数据

答对卡片、计数和进度在同一触发时刻更新；收入、图表和环比从同一数据派生；撤销恢复同一历史版本。不要分别手写看似接近的曲线或计数。内部一致只证明演示自洽，不能证明真实产品算法或收益。

### 20. 遮罩、复制画面与转场结束态都要检查

照片和遮挡层共用变换，检查主画面、背景副本、浮动预览、时间线缩略图。案例146使用预设锚点，不应描述为实测人脸追踪。转场完成后明确收敛到干净最终状态，避免残留旧画面碎条、两份正文叠字或近乎完成的裁切。

### 21. 技术和业务内容要有可核对依据

核对示例数据、公式、时间戳、命令先后和业务条件。案例149使用可独立复算的离线 AES-GCM 样例，但不代表完整 TLS 或真实传输；“天”和“工作日”也需要统一。能复算的实际复算，合成或说明性数据标明范围。

### 22. 任意时间点可确定性重现

按 core / animation 合同从时间计算状态，固定随机种子，必要时烘焙固定步长模拟。检查顺序播放、反向跳转与随机 seek 是否一致。不要依赖墙钟、调用次数或上一帧残留。用同一问题时刻复现修复结果。

### 23. 以最终编码文件为交付审查对象

分别检查源页面、捕获帧、最终 MP4，定位边缘黑条、坏帧、色彩转换或编码异常。项目曾出现编码后右侧8像素黑边；禁用某 SIMD 路径是定位后的局部补救，不是所有导出的默认参数。修编码时保留授权要求保留的声音和画幅，不能通过裁掉内容掩盖问题。

### 24. 检查范围、版本和证据绑定

正常速度播放看节奏，全线抽样看结构，关键区间密采看错位，原尺寸看细节，目标尺寸看层级。曾用0.5秒全线抽样和0.1秒重点采样：按风险选择，不能称为逐帧审完。记录实际查过的时间、文件 SHA、源码/脚本/素材版本；更换源或成片后更新受影响证据，不继承过期 PASS。

### 25. 手机适配是信息预算

在实际目标宽度检查主标题、关键数值与操作；减少同时出现的小字，细节可通过全屏阅读。交付展示站时考虑动态可用高度、浏览器工具栏、两个视频与控制区，说明/评论可分层展开，离屏视频暂停，音轨控制明确。模拟视口结果不能写成所有 iOS / Android 真机已验证。

### 26. 声音单独审查

保留已选声音，检查语速、停顿、重音、读音、音乐遮盖和动作落点。音轨存在、时长、LUFS、峰值、ASR或音轨一致性都不能替代实际试听。未试听就记录 pending / 未试听；不得伪造 human/listening review 或写“听感通过”。按现有音频/质检工作流处理交付要求。

### 27. 技术通过与参考质量分别判断

将解码/尺寸/时长、内容与状态、视觉、声音、参考差距分开记录。无穿帮不代表有表现力；局部像素变化、SSIM、动效数量或单帧相似度不代表审美接近。列明剩余字体、表演、材质、镜头和节奏差距；素材缺失、时长缩短和实现替代要在对比中可见。

### 28. 把导演决策前移

先验证最影响观感的字体构图、关键动作和镜头衔接，再批量完成整片。大批量任务用稳定的版本和审查机制组织，不能把所有题材套进同一个字卡模板。复杂角色表演、细腻材料和声音节奏仍可能需要额外资产/工具与反复审查；如实报告剩余工作，不把流程跑完等同于目标达到。

## 审查记录要求

可直接扩充现有审查文件；以下是记录字段，不是 CLI 自动识别的新证据格式。`evocut qa` 的机器证据格式仍由 `_evocut-local/QUALITY_GATE.md` 定义，不把本文字段当作自动通过凭证。

| 字段 | 记录内容 |
| --- | --- |
| 来源与范围 | 原 prompt、附件、参考文件/链接、已观察范围；缺失素材、代表片段与时长差异 |
| 版本 | 成片路径与 SHA256；实际源码、外部脚本/字体/素材身份；现有 render receipt 的覆盖边界 |
| 对照点 | 语义动作名，原片时间与新版时间，必要的前版时间 |
| 发现与修复 | 时间段、可见问题、改动、实际复查结果；未修复差距 |
| 视觉覆盖 | 正常播放或抽帧的实际方式、采样间隔/帧清单、重点区间、原尺寸/目标视口 |
| 声音覆盖 | 实际试听者/方式与范围；技术检查另列；没试听明确写未试听 |
| 结论 | 技术、内容、视觉、音频、参考接近程度分别说明；不得凭评分或标签抹去限制 |
| 已授权发布核对 | 页面实际引用的文件版本；如未发布则明确未发布，不把本地渲染当线上更新 |

独立复审适用于复杂或反复返工的片段，范围与风险相称；无需为每个小字修改调用多个审查者。反馈应关联实际成片版本，防止修复了旧版却让用户继续看到旧文件。
